design of the unit:
- PgLedger adapts the gateway LedgerPort (no Tx). It is bound to one household; reserve, settle and release each run one short transaction through the Store as the model role.
- reserve takes a per-household advisory lock (its own key, not the store's lock_household key), sums the month, then inserts. With the lock line removed, test_concurrent_reservations_stay_under_cap fails, so the test bites.
- An unset cap, or a cap not above zero, raises BudgetExceeded. A reservation past the cap raises BudgetExceeded and stores nothing.
- Month total counts held reservations at worst case and settled ones at actual cost, per household and UTC month.
- settle writes the llm_spend row and closes the reservation; settle or release of a closed, unknown or foreign reservation raises ValueError (caller bug).
- 80% alert (carry from WU-20 ruling 5): reserve_checked returns Reservation(id, alert); the reservation that takes the total across 80% of the cap carries a SpendAlert. The port form reserve returns the id and passes the same alert to an optional on_alert sink; a failing sink never fails a stored reservation.
