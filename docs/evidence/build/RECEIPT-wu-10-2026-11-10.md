How it behaves: `PgAuditSink.append` hashes the subject, each `sensitive` value and the whole payload with `KeyRing.hmac` (audit key) and calls `control.audit_append` in the caller's transaction or its own. A sensitive value appears only as `<name>_hmac` in `detail`. Any store, key or timeout error raises `AuditUnavailable` carrying only the exception class name, with no cause attached, so callers fail closed and nothing is dropped quietly. A blank run id raises `ValueError`; an event for another household than the transaction raises `ValueError`. A caller transaction is never given a timeout (cancelling a statement inside it would poison it); the sink's own transaction has one (default 5 s).
